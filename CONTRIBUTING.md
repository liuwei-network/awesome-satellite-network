# Contributing

Thank you for helping improve Awesome Satellite Networking.

## Scope

The collection focuses on satellite networking and non-terrestrial networks, including architecture, topology, routing, mobility, resource management, ground systems, physical-layer networking, transport, measurement, space computing, sensing, satellite IoT, content delivery, security, reliability, and experimental platforms.

The core paper list prioritizes full conference papers from CCF A/B venues. Journal papers are not included. Clearly relevant workshop or position papers may be listed in the Workshops or Other venue sections.

## Add a Paper

Before opening a pull request:

1. Search both [README.md](README.md) and [PAPERS_BY_VENUE.md](PAPERS_BY_VENUE.md) for the title and DOI.
2. Use the official paper title and a stable publisher, conference, DOI, or author-hosted URL.
3. Confirm the venue, four-digit year, and CCF rank.
4. Add the paper to every research direction where it makes a substantial contribution.
5. Add it exactly once to the appropriate venue section.
6. Keep entries ordered by year, newest first; within a year, sort alphabetically by title.

Use this format in the research-direction index:

```markdown
- [Paper title](https://example.org/paper) — `VENUE 2026`
```

Use this format in the venue index:

```markdown
- [Paper title](https://example.org/paper) — `VENUE 2026` · `Topic`
```

If the paper has a recognized award, append `🏆 Award name`.

## Add a Project, Dataset, or Tool

Each resource should include:

- a stable official URL;
- one concise sentence explaining what it provides;
- an appropriate subsection;
- evidence that it is publicly accessible.

Avoid duplicate forks, abandoned mirrors when an official repository exists, commercial landing pages without research utility, and resources without enough documentation to evaluate.

## Pull Requests

Keep each pull request focused. In the description, explain:

- what was added or corrected;
- why it is in scope;
- the selected research direction or resource category;
- any cross-topic placement;
- whether code, data, or artifacts are available.

All links and Markdown checks should pass before review.

## Corrections

Broken links, incorrect titles, venue names, years, duplicate entries, and classification improvements are welcome. When replacing a URL, prefer the DOI or official publication page.
